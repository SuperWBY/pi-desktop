# Pi Desktop 长任务执行与 Computer Use 路线

## 目标与验收原则

围绕用户委托的行业研究、平台后台操作、数据上传下载和跨应用执行，构建能够制定计划、持续执行、验证成果、在需要时交还控制权的个人 Agent。Pi 是运行引擎；任务状态、权限、记忆、执行与验收由桌面产品层负责。以可复现的任务结果与用户实际价值衡量，不预设“超越所有产品”。

验证层级：单元测试 → 隔离集成测试 → **由 Launch Services 正常启动的已授权 Pi Desktop 实际进程** → 跨更新及故障注入 → 指定场景真实试用。浏览器、桌面和外部系统分别记录；UI 变化或模型回复不能代替目标结果验收。

## 阶段 0：真实闭环和基线（当前优先）

1. **已完成一例**：在隔离的临时测试应用中完成一次观察 → 选择目标 → 授权 → 原生操作 → 独立读取结果；记录进程归属、签名、目标、时延和每次动作结果。不访问用户业务页面、不传输用户内容。必须验证旧快照、目标变化、并发、取消与失败后重试。
2. **已核验本例**：验证 Pi Desktop 真实 TCC 身份；通过 Codex、终端或测试进程继承到的权限不能冒充 Pi Desktop 的授权。保留确定的测试日志和无敏感内容的证据。
3. 建立固定本地任务集及输入、清理、客观验收：单应用按钮/表单/列表、窗口切换、中文文本、动态加载、异常重试和人工接管。每次运行隔离环境与随机种子；标记人工步骤。
4. 桌面坐标/OCR 点击需绑定应用、窗口、前台状态、屏幕坐标和视觉证据，在执行前重新验证；不满足条件时停止并要求重新观察。检查多显示器、缩放、窗口移动和遮挡。
5. 对动作结果定义成功、失败、未知三态；只有幂等且确认未执行的动作才能重试。各步骤必须有观察及可验证的目标后置条件。

**退出条件：**真实 Pi Desktop 成功完成闭环与故障注入，得到可复现的基准结果；仍有限制的能力明确标识，不让界面暗示已完成。

## 阶段 1：可靠执行核心

- 执行管线统一为目标识别 → 校验目标、权限及可操作性 → 执行 → 等待稳定 → 检查期望结果 → 记录证据；参考 Playwright 的动作前可见、稳定、可交互与动作后断言。
- 异常分为目标改变、窗口切换、超时结果未知、权限失效、连接中断与验证码；只自动重试只读或已证明幂等的步骤。
- 初步加入只读的动态控件等待，需在真实后台继续验证；动作本身不自动重试。
- 逐步扩展任务取消、可暂停、人工接管、续跑；保留操作记录与撤销信息，敏感操作在实际提交前确认。
- 默认保守处理不可信网页、消息、截图与文件中的指令；不能以观察材料改变用户授权边界。独立审计、有限的截图保存与删除策略。
- 实现每应用允许范围、必要时隔离浏览器配置；不要绕过网站验证或安全保护。

**验收：**故障注入时不发生重复提交；任务可恢复并记录可审计证据。以实际测得结果报告成功率、人工介入率、时延和成本。

## 阶段 2：长任务引擎

- 目标、约束、成功标准、阶段、步骤、证据、阻塞原因和版本组成持久任务记录；用户可查看、编辑、暂停、取消。
- 计划和执行分层：规划器生成可审阅步骤；执行器一次领取可验证的短步骤；验证器根据证据判断；失败后受限重规划。
- 每个外部写入步骤定义授权、幂等键、前置检查、结果回读、未知结果处置。重启恢复先核对真实状态，再决定继续，不重复提交。
- 设置预算（时间、步骤、模型开销、重试次数）、检查点和循环检测；耗尽时暂停并说明原因。

**验收：**在中断、应用重启、网络失败与用户接管后，能从持久状态恢复；任务完成必须有目标级证据而非仅有步骤日志。

## 阶段 3：行业研究与交付

- 平台后台场景纳入单网页多步骤、跨网站和跨应用三种任务：查找记录、下载、校验与整理数据、准备上传、提交前确认、提交后读取结果；使用测试账号和本地模拟后台建立可复现基线。
- 操作前校验页面、账号、目标记录、文件类型与业务条件；上传前核对内容与目的地，提交后独立回读。服务端结果未知时先查询状态，不盲目重试提交。
- 以页面可操作状态和结果信号代替固定等待，记录每步耗时；保持平台允许的访问频率，不绕过验证码或安全机制。
- 面向行业研究，区分用户事实、外部资料和推断；记录来源、时间、方法、冲突与置信度，明确查证范围和日期。
- 把采集、去重、分析、文档产物、人工复核拆为可恢复步骤；支持中文业务站点与本地文件，遵循平台访问限制。
- 用户提出“执行”时，先构造具体对象与成功标准；涉及外发或高影响变更时，先备好可审查结果，再取得所需授权。
- 记忆优先保存用户明确偏好；自动推断仅为可编辑、可删除、带来源和范围的候选，敏感信息不默认沉淀。

**验收：**同一批真实授权业务任务可以从问题到可复核成果全程追踪；失败点可定位、来源可回看。

## 阶段 4：对照测试和持续优化

- 基线分别选择：Pi 的 In-App/CDP/Extension、Playwright 脚本基线、可合法运行的其他 Computer Use Agent；相同初始环境、账号权限、任务与评判器。脚本基线和自主 Agent 分开统计，不把不同类型任务混为一谈。
- 指标：最终任务成功率、步骤成功率、重复副作用、不可恢复失败、人工接管次数、完成时长、模型及运行费用、数据暴露和测试重复次数；发布原始汇总及失败案例。
- 使用 OSWorld-Verified/OSWorld 2.0 等公开任务参考复杂度和客观评估；Mac 本地测试与 Linux 基准必须分别报告，不直接混算。
- 每次优化先确定基线和失败根因，在隔离任务集复测；比较前记录模型、版本、提示、工具、预算与执行日期。

## 当前已知限制

- 已完成一例真实已授权 Pi Desktop 原生按钮观察、确认、点击与结果回读；仍需真实故障注入、多应用及网页流程验证。隔离测试进程的 TCC 责任主体可能是 Codex，不可据此判断 Pi 的系统权限。
- macOS AX 目标身份检查不是安全沙箱，坐标及 OCR 的窗口/视觉绑定仍未完成。
- 目前固定自签名证书仅服务本机开发；生产分发需考虑 Apple Developer ID、公证及更新迁移。
- 网站验证码和反自动化处理以识别、暂停和人工接管为主；不承诺绕过。
- 计划中的基准指标与目标需先测得基线，再设定数值，不虚构领先或成功率。

## 首批业务验收场景

| 场景 | 测试输入 | 验收证据 | 风险与恢复 |
|---|---|---|---|
| 后台查找 | 模拟账号、记录编号、筛选条件 | 记录标识和筛选条件匹配；结果可回读 | 列表延迟、分页和同名记录；不得凭首个匹配直接提交 |
| 下载数据 | 模拟报表、日期范围、期望文件类型 | 下载完成、文件存在、大小和格式正确，必要时比较校验和 | 中断只重试可确认未完成的下载；文件名冲突不得静默覆盖 |
| 数据整理 | 测试表格、列映射与校验规则 | 行数、关键列、异常行和输出文件可核对 | 保留原文件；发现缺列、编码异常或异常行即暂停 |
| 上传与提交 | 模拟后台、明确指定的测试文件和目标记录 | 上传后的文件名、目标记录、服务端状态回读；最终结果与输入核对 | 上传前核对来源和目标，外部提交须获得所需授权；超时先查服务端状态，不能盲目重传 |
| 跨系统任务 | 两个本地模拟后台与临时文件 | A 的导出、转换、B 的导入及服务端回读形成完整证据链 | 可从检查点恢复；同一业务记录不得重复创建 |
| 人工接管 | 模拟登录或验证挑战 | 暂停后用户处理，恢复前重新观察并核对账号和页面 | 不破解验证、不继续点击；取消后保持暂停 |

## 本轮基线与下一步

- 会话切换检查：主进程为不同会话保留独立 Pi 子进程，但渲染层原来在重新进入会话时忽略 `get_state.isStreaming`，一律显示已停止。现按该状态恢复运行标志；无窗口界面回归覆盖返回运行中状态，`scripts/test-background-session.mjs` 在隔离 Electron 中验证模拟 Pi 进程切走后继续运行、切回后完成并可读取最终消息。
- 上述测试不覆盖真实模型、切换期间的流式增量、并发完成时序或权限确认。主进程当前只转发前台进程的事件；后台发出的确认请求可能无法展示，切换期间已展示的请求也需要绑定原进程。恢复状态和审批链路未完成之前，不能声称后台长任务可靠，应避免在等待人工确认时切换会话。
- 针对上述审批缺口，主进程现在按 Pi 进程缓存确认等交互请求，切回时恢复；界面使用独立标识，非当前进程或已过期的响应被拒绝。`scripts/test-session-ui-requests.mjs` 覆盖相同原始 ID、超时和清理；`scripts/test-background-confirm.mjs` 使用隔离 Electron 与两个模拟 Pi 进程，验证后台请求恢复、界面切换及响应不串会话。后台请求目前不会主动通知用户；真实模型、Pi RPC 超时边界、进程崩溃及切换过程中状态竞态仍需验证。本条替代上一条对确认请求尚未处理的描述，不代表后台长任务已经可靠。
- `scripts/test-background-confirm-real-pi.mjs` 使用隔离 Electron 和两个真实 Pi RPC 子进程，通过临时项目命令发起确认，验证后台请求恢复、界面确认和旧响应不串会话；不调用模型或真实业务。测试发现新会话文件未落盘时，切回活进程会被错误拒绝，已调整为先查找活进程，再验证待重启会话的文件。后台待确认提示、进程崩溃、模型长任务与切换竞态仍需验证。
- 后台确认现会在侧栏显示“后台任务等待确认”，点击切回对应会话；确认、超时或进程退出后更新提示。隔离 Electron 与两个真实 Pi RPC 进程的测试覆盖提示出现、点击进入、不同会话确认和完成后消失；单元测试覆盖超时状态更新。当前提示依赖应用进程中的实时状态，应用重启后的待办恢复、真实业务任务与系统通知仍未验证。
- 崩溃基线：`scripts/test-interrupted-confirm-baseline.mjs` 在隔离 Electron 和真实 Pi RPC 中发起待确认请求，强制终止 Electron 并重启。结果是旧确认没有重放，尚未落盘的会话无法重开，也没有中断提示。后续应持久化最小的待确认/中断状态，明确让用户核对；不能恢复或自动批准已经失效的确认。本测试不涉及真实业务，不证明所有崩溃时序。
- 已接入确认中断记录：确认出现前写入最小项目和会话标识，不保存确认内容；未处理请求在重启或子进程退出后显示中断提示，用户可确认已知晓。记录不能写入或更新时取消确认。上述隔离崩溃测试现在验证提示、旧弹窗不重放及提示确认后重启不再出现；真实 Pi 双会话测试验证已答复的请求不会留下错误中断提示。此机制只覆盖等待确认期间，不证明批准之后的动作结果、其他中断时序或突然断电时的持久性。
- `scripts/test-approved-action-crash-baseline.mjs` 验证了真实 Pi RPC 在确认后、命令结束前崩溃时，确认中断提示不会出现；这与浏览器动作日志是不同范围。现为内置原生桌面单步和批量动作新增独立事务记录：执行前写入，失败或进程中断时阻止后续桌面动作；用户观察并核对结果后，可通过 `computer_use_desktop_reconcile` 显式清除记录。界面将明确的未知结果标为待核对。隔离测试覆盖进程被杀、并发阻止、拒绝恢复和批量失败；尚未在已授权安装版用真实桌面动作注入崩溃，确认后的普通 Pi 命令也不在此保护范围内。辅助程序返回成功不等于业务结果成功，仍需独立回读。
- `scripts/test-helper-parent-crash-baseline.mjs` 用隔离 Node 父子进程证实：父进程被强制结束后，子进程仍可能运行并完成操作。当前桌面日志只检查 Pi 进程存活，不能证明其启动的原生辅助程序已停止；恢复提示现要求用户确认操作停止，但尚无自动保证。桌面动作日志的新版本不应据此认定可安全发布，需先建立辅助进程生命周期约束并用真实原生动作验证。
- 可行方向待实现并验证：让执行操作的原生辅助程序先等待启动信号，将其进程身份写入事务记录后再允许执行；恢复时同时核对执行进程是否仍存活。必须测试父进程在启动信号前后被杀、辅助进程退出、PID 复用以及多次辅助调用；Windows 路径需要单独设计，不能直接假定 macOS 行为适用。

- 安装版模型驱动的本地上传测试：`opencode-go/deepseek-v4.1-flash` 自行调用应用内浏览器工具查询、上传和提交；Codex 处理操作确认和系统文件选择。模拟后台独立核对目标订单、文件哈希、上传及提交各一次。界面记录 29 次操作、3 次错误、3 分 38 秒；模型两次未先重新观察被拒绝，随后恢复。文件选择经人工接管确认后再次调用核验工具报无待处理选择；模型转而依据可见文件元数据继续，不能证明文件路径和内容由模型核验。原始结果见 `evidence/2026-11-07-model-inapp-upload.json`，仅一次本地测试，不代表真实平台或生产成功率。
- 此次测试发现模拟后台提交后查询仍显示待处理：服务端提交状态与查询接口不一致。现已修正模拟后台并添加回归，后续需要在修正后的后台重新运行模型任务；不能把修正后的表现套用到本次结果。人工接管的工具反馈也已说明选择已结束及其核验边界，尚需再次用实际模型验证是否减少误调用。

- 已在实际安装的 Pi Desktop 进程中完成一次本地 AX 按钮闭环，结果见 `docs/computer-use/evidence/2026-11-07-macos-fixture.json`；该证据不代表真实业务后台已通过。
- 已增加浏览器只读等待，能够处理延迟出现的唯一目标；记录观察次数和耗时。单次后端观察可能超过等待窗口，且控件出现不等于业务完成。
- 下一批依次完成：① 可复现的本地模拟后台与客观结果检查；② 文件下载与上传的明确接口及权限约束；③ 服务端确认和未知结果恢复；④ 与 Playwright 和其他 Agent 使用同一批任务对照。
- 基准必须在完成前冻结任务定义与评判规则；记录模型、版本、执行次数、各项失败及其原因。初始样本不足时只报告原始结果，不给出“生产级成功率”。

## 内置浏览器下载回归

- 隔离 Electron 窗口中，重开浏览器曾使同一 session 的下载监听从 1 增到 2；同名下载完成提示还会被按文件名去重。现已在关闭时移除对应监听并为每次下载分配唯一标识。
- `E2E_ONLY=browser-downloads npm run e2e` 验证重开后的监听数量、两次同名文件实际落盘及独立完成提示。测试通过测试代码指定隔离目录，未验证真实用户操作系统保存对话框。
- Agent 现可通过内置浏览器会话查询会话开始后的下载记录；该记录可能来自用户或其他操作，并未证明与特定动作的因果关系，文件完整性仍须独立验证。下载进度、文件重名和失败恢复仍需进一步设计和验证。

- 在隔离 Electron 测试中，认证桥返回完成、取消及文件路径和字节数；验证新会话排除旧下载、桥接重启后拒绝混用记录。测试保存路径由测试程序指定，真实保存对话框、具体动作关联、内容校验和 CDP / 日常 Chrome 下载仍未验证。

- 安装版手动验证：通过 Codex Computer Use 在 Pi Desktop 内打开本地后台、使用 macOS 保存对话框选择临时目录，核对文件字节及本机桥接记录；再次打开保存窗口并取消，记录为 `cancelled` 且无保存路径。证据见 `docs/computer-use/evidence/2026-11-07-inapp-save-dialog.json`。这是人操作安装版 UI，不代表 Pi 自主完成下载。

## 网页状态文本回读

- 新增统一会话只读文本工具，要求先观察当前页面，并校验页面地址和快照；人机验证出现时暂停。应用内、CDP、Chrome 扩展各有隔离测试。输出限长并提示截断，不读取表单值和可编辑区域，也不覆盖 iframe 或 shadow DOM；网页文本是不可信数据，可能含敏感信息或被视觉遮挡，不能作为隐私过滤器。
- 模拟后台测试中，Pi 的 CDP 路由执行上传和提交按钮并读取状态，服务端独立核对订单编号、文件哈希与提交次数。文件由 Playwright 测试程序选择，确认由测试桩接受；未验证 Pi 自主选择文件、真实用户确认或生产平台提交。
- 安装版 In-App 浏览器完成一次本地上传与提交验证：测试程序通过 Pi 的认证浏览器桥打开真实 macOS 文件选择窗口，Codex Computer Use 在窗口中选择临时 CSV，随后脚本通过桥查找订单、上传和提交；本地服务端独立确认订单、上传与提交各一次，文件 SHA-256 一致。证据见 `evidence/2026-11-07-inapp-native-upload.json`。该测试没有调用 Pi Agent、模型、审批或动作日志，文件选择由 Codex 操作，不能证明自主上传能力或生产网站可靠性。
- 点击可见文件输入后，统一会话暂停浏览器动作并保留跨进程记录，提示处理系统文件选择窗口；可由桌面操作或用户选择，再调用 `computer_use_session_verify_file` 用精确文件名检查单个文件的名称、大小和类型。匹配输入时只使用页面地址和唯一标签，不证明元素身份、源路径或内容；原先已有文件、文件名不符、页面变化或结果不完整时保持暂停。若由用户确认接管，系统仍会重新观察并要求恰有一个文件；用户确认了空选择时不恢复。用户明确确认系统窗口已关闭后，可取消文件选择并释放记录。检查成功也不证明上传成功，后续仍须独立核对业务结果。
- CDP 隔离业务测试覆盖 Pi 工具打开选择器、暂停和保留记录、由 Playwright 测试程序选择文件、Pi 工具验证元数据并释放记录，再执行上传；另外验证用户拒绝取消时保持记录、确认取消后释放记录。隔离 Chrome 扩展测试同样覆盖打开选择器、测试程序选择文件和核对记录。本地 macOS 选择窗口的测试与这些测试是不同验证，不能合并称为 Pi 自主完成了原生文件选择。自定义上传按钮、隐藏文件输入、iframe 和 shadow DOM 尚未纳入上述引导。

## 上传文件选择核对

- 三种浏览器会话的文件输入候选返回文件名、字节数、类型、总数和截断标记，不返回文件内容或本地路径。每次观察还记录主文档中所有文件输入的元素、文件对象身份及文件元数据；后续动作前若选择改变，要求重新观察。超过设定数量上限时停止观察。
- 隔离测试覆盖选择变更后旧上传按钮被拒绝、重新观察后的元数据、20 项输出上限、超限停止，以及模拟后台上传和服务端核对。文件由测试程序选择；真实系统选择窗口和自主选文件仍未验证。
- 此检查不计算内容哈希，文件元数据相同不代表内容相同；也不覆盖 iframe、shadow DOM、恶意页面或校验后的竞态。提交前仍需核对文件和目标，提交后独立回读服务端结果。
- 增加确认窗口期间的替换测试：即使新旧文件名称、大小、类型和修改时间相同，只要浏览器中的文件对象改变，旧动作也会被拒绝；模拟后台证实未发生上传。确认窗口会展示页面、目标和观察到的可见文件摘要，提示这些文件不一定属于当前动作。隐藏输入、iframe 和 shadow DOM 的文件不保证出现在摘要中；文件对象身份检查依然不是哈希或安全沙箱。

## 脚本驱动的业务任务基线与 CDP 导航

- `scripts/benchmark-business-workflow.mjs` 让两条脚本路径在隔离本地后台完成查找指定订单、上传 CSV、提交；服务端独立核对订单、文件名、SHA-256、大小及副作用次数。每次使用新浏览器配置和后台状态，交替执行顺序。文件由测试程序选择，Pi 确认由测试桩接受，没有模型或真人参与。
- 发现 CDP 导航原先固定等待 700 毫秒：简单页面平白等待，慢页面则可能在正文到达前观察。现改为监听对应文档的 DOMContentLoaded 或 load，等待最多 15 秒，并处理跳转和导航错误。同文档跳转不等待新文档事件；动态业务数据仍需要另行等待和验证。
- 同一任务各三次，调整前 Pi 脚本为 827、832、865 毫秒，调整后为 104、110、180 毫秒；调整前 Playwright 脚本为 206、240、251 毫秒，调整后为 203、240、244 毫秒。两条路径均 3/3 通过，且没有重复上传或提交。原始数据见 `evidence/2026-11-07-business-tool-baseline.json` 与 `evidence/2026-11-07-business-tool-after.json`。
- 计时不包含浏览器启动、服务端独立回读或真人确认；Pi 的脚本初始化与观察步骤和 Playwright 脚本不同。样本很小，也未覆盖下载、真实网站、验证码或自主规划，因此不能据此比较产品整体速度、可靠性或生产成功率。

## 已确认动作与后续读取失败

- CDP 动作已获得浏览器返回后，如果随后读取页面状态失败，原实现会把整个动作报错。调用方可能因此误以为动作未发生；现保留已确认动作的返回值，并标记 `pageStateUnavailable`。统一会话继续尝试独立观察，页面状态与业务结果仍需核对。
- 隔离 Chrome 测试在真实点击成功后注入后续读取错误，确认动作只发生一次且返回标记。此修复只覆盖浏览器已确认动作之后的读取失败；如果动作请求本身超时或连接中断，结果仍可能未知，必须先核对页面和服务端状态，不得盲目重复提交。

## 动作结果未知时的人工核对

- 统一浏览器路由在动作发送之前写入事务记录；动作调用抛错或进程中途退出时保留记录。仍可只读观察当前页面，但不能继续执行动作或导航；关闭再打开会话和重启 Agent 都不会清除记录，旧版浏览器动作与 CDP 导航也使用同一记录。人工接管对话框明确要求先检查业务结果，用户确认后才尝试解除对应记录。
- 隔离 CDP 测试在真实点击之后模拟丢失响应，确认点击已发生、重新观察无法重复点击、拒绝人工确认时保持暂停；另以模拟适配器覆盖应用内和 Chrome 扩展桥的典型传输错误。尚未在真实业务平台或三个真实后端中注入断线。
- 模拟后台的 CDP 业务测试还覆盖了订单提交：执行提交点击后人为丢弃动作响应，通过页面及独立服务端状态确认订单已提交、未重复提交；拒绝人工确认时保持暂停，再确认后恢复。文件仍由测试脚本选择，响应丢失由测试注入，并非真实网络故障。
- 此记录只约束使用同一数据库且接入本机制的 Pi 浏览器工具，不能阻止用户、其他自动化程序或未接入的第三方工具操作；浏览器确认动作不代表服务器已提交。为防止不同后端操作同一业务系统时绕过保护，所有后端共用一个待处理槽位，导致浏览器动作串行。动作抛错保守保留记录，某些执行前的拒绝仍可能要求人工确认。
- CDP、In-App 和 Chrome 扩展桥的页面身份、目标和人机验证检查会在实际动作前返回明确的结构化拒绝。收到该结果并成功清除记录后，只需重新观察或处理验证；若拒绝响应丢失或记录清除失败，仍标记结果未知。CDP 模拟后台测试覆盖标签变化、确认期间替换文件、拒绝响应丢失和服务端无写入；隔离 Electron 与 Chrome 扩展测试覆盖目标变化、人机验证及模拟响应丢失，并核对没有触发点击。Chrome 桥结构化响应由认证协议保护，且只在 Pi 请求协议版本 1 时启用；旧客户端仍收到原有错误，旧扩展仍按保守方式处理。真实网络故障和生产网站尚未覆盖。
- 2026-11-07 本机验证：安装版准备了 Chrome Bridge 0.1.10，Chrome 扩展页刷新后显示 0.1.10，认证连接检查返回 connected。此检查仅证明当前桥接握手成功；结构化拒绝、人工核对及故障注入仍是在隔离 Chrome 测试中验证。
- 操作结果未知时，桌面工具卡片及其折叠分组显示“操作结果未知，请核对”，不再标成普通操作失败。Electron 隔离界面测试覆盖单组折叠和展开；此展示依赖当前路由的明确错误文本，未来应改为稳定的结构化状态协议。

### 跨重启恢复的实现要求和验证

1. 在发送可能产生副作用的动作之前，持久记录随机操作 ID、浏览器范围和待确认状态；写入失败时不得执行动作。不能只在捕获超时后写入，否则进程崩溃会漏掉正在执行的动作。
2. 每个操作独立记录，避免多个聊天相互覆盖；限制数据内容，不保存页面文本、输入值、完整 URL 或文件路径。并发操作的读取、写入和确认需有跨进程一致性保护。
3. 只有明确收到动作结果，才能将记录推进到下一状态；重启发现未结束的操作时需先展示待核对状态。自动页面变化不等于业务成功，用户确认必须针对相应操作，而不是清空其他任务的记录。
4. 验证崩溃发生在发送前、发送中、收到响应后及确认过程中的各个位置；覆盖多个进程同时启动、写入失败和记录损坏。对实际业务后台仍需独立核对目标记录及服务端状态，不能承诺精确一次执行。
5. 文件系统方案需处理“读取旧标记后，另一进程删除并创建新标记，再误删新标记”的并发竞态；单纯检查文件名或删除前比较内容不足以消除该竞态。事务存储可作为候选，但必须先核对 Pi 实际 Node 版本与跨平台兼容性，再通过独立进程和崩溃注入测试。

- SQLite 事务记录组件 `extensions/computer-use/src/browser-action-journal.ts` 已接入统一浏览器路由、旧版浏览器动作及旧版 CDP 导航。记录只包含后端、随机操作 ID、进程标识和时间，不包含页面或输入内容；各后端共享一个待处理槽位，删除须匹配操作 ID，其他进程不能解除仍存活进程持有的记录。
- `scripts/test-browser-action-journal.mjs` 在本机 Node 26 上验证八进程竞争、记录重开、错误 ID、活进程保护、持有记录的进程被强制终止、未提交事务回滚和数据库损坏。`scripts/test-browser-router-journal.mjs` 覆盖写前记录、存储失败不执行、跨后端阻止、浏览器保留及动作发送后进程被杀。`scripts/test-browser-journal-pi-router.mjs` 验证本机真实 Pi 进程能够在开启浏览器会话时发现隔离数据库中的待核对记录。
- 模拟后台的 CDP 测试启用真实事务记录，模拟提交后丢失响应，再新建路由读取记录，确认用户核对前无法重试；文件选择、确认及故障均由测试程序模拟。PID 复用可能导致保守阻塞；若原进程仍存活，其他进程不能解除其记录。尚需验证真实网络故障、实际安装版完整重启恢复、Windows、存储权限和更细的崩溃时序，不能据此声称精确一次执行。
- 接入记录后，同一模拟任务各三次均通过，Pi 脚本为 108、112、174 毫秒，Playwright 为 201、242、250 毫秒，数据见 `evidence/2026-11-07-business-tool-journal.json`。样本少且不含模型和真人确认，不能作为产品性能或可靠性排名。
- 此后曾发生一次并行运行时的 CDP 导航超时；单独复测及三组同时运行的回归均通过。因为没有再次复现，根因仍未知，不能将其视为已修复。

## 原生桌面动作与进程中断保护

- 桌面动作在调用辅助程序前写入独立事务记录；辅助程序等待启动信号，记录其进程 ID 后才开始执行。执行结果未知时阻止后续接入该机制的桌面动作，需在辅助进程停止后由用户检查实际结果并确认恢复。进程 ID 复用可能造成保守阻塞；该机制无法阻止其他工具或用户操作，也不保证业务操作恰好执行一次。
- 2026-11-07 在已授权的安装版 Pi Desktop 启动的 Pi 进程中，通过隔离测试命令加载当前源码，观察本机测试窗口、点击原生按钮、再次观察到状态变化，并核对测试文件和空的待处理日志。该命令预先接受测试动作的确认请求，不代表正式审批链路或模型自主操作；测试文件没有计数，不能证明实际点击次数。
- 隔离进程测试覆盖记录失败、放行前后父进程终止及仍运行的辅助进程阻止恢复；尚未在实际原生动作执行时注入崩溃，也未验证 Windows。当前受保护的桌面动作在 Windows 明确拒绝执行，不能作为 Windows 发布版本。
- 随后用修复后的可计数本地夹具重测：安装版界面显示目标应用、窗口和按钮，确认后由 Pi 进程加载当前源码完成原生点击；独立文件记录一次点击，再次观察到按钮变化，事务与辅助进程记录为空。见 `evidence/2026-11-07-native-approved-action.json`。测试通过脚本命令调用工具，未使用模型规划，也未在原生动作期间注入崩溃。
- 回归命令 `npm run test:computer-use` 在本次终端环境的辅助功能权限预检处失败，未进入 TextEdit 验证；该终端启动的 helper 不等同于已授权 Pi Desktop 进程。类型检查、隔离动作日志与进程测试、界面状态测试，以及上述安装版进程中的本地真实动作分别通过。
- 桌面动作后的快照比较现将消失的元素计入变化，状态使用 `changed` 而非 `confirmed`，并提示界面变化不证明业务成功。动作已发送但随后无法观察时，提示先核对结果再决定是否重复；隔离测试覆盖元素变化、消失和观察失败。元素 ID 在每次观察时重新编号，因此比较仍只是启发式证据，不能证明控件身份或业务结果；坐标、OCR 和焦点输入仍缺少与原生控件相同的身份核验。
