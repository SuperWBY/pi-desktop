# 真终端（PTY Terminal）实现方案

目标：把右侧工作面板的「终端」从命令运行器升级为真正的交互式终端——跑用户自己的
`$SHELL`（macOS 默认 zsh），继承 `.zshrc`、Oh My Zsh 主题、别名与环境；vim、htop、fzf
等交互式程序可用。Windows 经 ConPTY 跑 PowerShell/cmd，形态一致。

背景：现终端是"输入命令 → 执行 → 显示输出"的运行器（pi RPC `bash` 命令，600s 超时，
输出截断 40 万字符），用户自己的 shell 配置、交互式程序、提示符主题都用不上。

---

## 1. 竞品做法

- **VS Code 集成终端**：xterm.js（渲染）+ node-pty（伪终端），每个终端一个 PTY 进程，
  默认用户的登录 shell；支持标签、分屏、搜索、链接识别、滚动缓冲。
- **iTerm2 / 终端.app**：完整终端模拟器，用户配置（主题、提示符）即所见。
- **Cursor / Windsurf**：直接复用 VS Code 的 xterm.js + node-pty 方案。
- **共同结论**：PTY + xterm.js 是桌面应用嵌终端的成熟标准路径，无需自研渲染。

## 2. 技术选型

| 组件 | 选型 | 说明 |
| --- | --- | --- |
| 渲染 | `@xterm/xterm` + fit/web-links/search addon | 成熟、可访问性支持好；视图层只做功能，视觉跟随应用 tokens |
| PTY | `node-pty` | 主进程持有会话；Windows 走 ConPTY；需按 Electron ABI 预编译 |
| IPC | 复用现有 `send()`/subscribe 模式 | `pty:spawn/kill/write/resize/data/exit`，会话 id 关联 |
| Shell | `$SHELL`，缺省 zsh；Windows 缺省 PowerShell | 以登录 shell 启动（`-l`），cwd = 当前工作区 |

备选被否：继续自研命令运行器（无法满足交互式程序）；WebView 嵌外部终端
（跨进程 UI 联动复杂，牺牲键盘与主题一致性）。

## 3. 架构与边界（功能层）

- **终端是用户自己的 shell，不属于 pi 的权限体系**：不进 pi 沙箱、不经工具审批；
  文档与设置说明中明确这一边界（用户手动操作 = 用户全权，与 agent 的 bash 工具分开）。
- **pi 的 bash 工具保持不变**：agent 在会话里跑命令仍走 RPC + 审批 + 上下文排除；
  终端页只是用户手动操作的入口。
- **降级路径**：node-pty 加载失败（ABI/编译问题）时自动回退现有命令运行器，
  终端页永远可用；设置里提供「使用旧版命令面板」的手动开关。
- **"同步给 Pi"的替代**：运行器时代的上下文排除开关，在真终端下由联动能力取代
  （见阶段 3）：选中输出 → 一键作为上下文发给 composer；agent 默认看不到终端内容。

## 4. 阶段拆分与验收

### 阶段 1：单终端可用

- 主进程 PTY 会话管理：spawn（默认 `$SHELL -l`、cwd=工作区）、write、resize、kill；
  窗口关闭/工作区切换时回收会话；进程退出后终端内提示并支持重启。
- 渲染：xterm 接管终端页；键盘、选中复制、粘贴、⌘K 清屏、滚动缓冲；窗口 resize
  跟随 fit。
- 打包：node-pty 随 pack 嵌入（非 asar 预编译产物入包）；dev 与打包两种形态启动路径
  都要验证。
- 验收（真机 macOS）：Oh My Zsh 主题提示符原样显示；vim/htop/⌃C/⌃D 行为正确；
  长输出滚动流畅；切换会话/工作区后 PTY 正确回收；降级开关生效。

### 阶段 2：体验补齐

- 多终端标签（新建/关闭/切换），与会话生命周期解耦。
- 搜索、链接点击打开浏览器、字号设置；主题跟随应用深浅色切换。
- 验收：多标签互不串流；搜索命中滚动；深浅色切换终端配色跟随；窄窗口可用。

### 阶段 3：与 Pi 联动

- 选中终端输出 → 「发给 Pi」（进 composer，作为普通消息附件）。
- 「把上一条命令与输出作为上下文」一键操作。
- 可选（默认关）：agent 的 bash 调用转发到可见终端展示。
- 验收：联动内容进上下文有明确展示与撤销入口；默认不自动同步。

## 5. 风险

| 风险 | 处理 |
| --- | --- |
| node-pty 需按 Electron 45 ABI 编译，升级 Electron 需重编译 | CI 固化预编译步骤；加载失败自动回退运行器 |
| 打包遗漏原生产物 | pack 脚本显式断言 node-pty 产物存在（延续 check-pack-auth 思路） |
| 大量输出渲染压力 | xterm 滚动缓冲上限；必要时引入 WebGL addon |
| PTY 会话泄漏 | 主进程持有会话表，窗口关闭/quit 全量回收（延续 before-quit 模式） |
| 用户混淆终端与 agent 权限 | 设置与文档写明边界：终端 = 用户本人操作，不经沙箱与审批 |

## 6. 非目标

- 不做分屏、SSH 客户端、tmux 集成。
- 不改变 pi agent 的 bash 工具与审批体系。
- 不做终端主题自定义市场；视觉跟随应用主题。
