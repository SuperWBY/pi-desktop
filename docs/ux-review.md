# Pi Desktop 体验梳理：动效、流利度、交互、UI、文案

> 范围：当前 Pi Desktop 的聊天主界面、首次启动、设置、权限/沙箱、工作面板、浏览器与 Computer Use。
> 目标：让第一次使用的人知道“下一步做什么”，让长期使用的人感觉“快、稳、安静”，而不是先学习一套工程术语。
>
> **已确认的产品决定（以此为准）**：保留 `API Key` 这个实际叫法；保留 `自动压缩上下文`；不把设置重排成 5 组，继续使用现有分类，只做描述、顺序和状态摘要的轻量优化。

---

## 0. 一句话结论

**视觉气质已经成立，但产品语言仍然像开发者工具。**

现在的 Pi Desktop 有很好的纸墨色、紧凑布局和完整能力，但用户要理解 `运行时`、`服务商`、`沙箱`、`workspace-write`、`JSONL`、`stderr`、`provider`、`token` 之后，才能完成配置或判断风险。  
下一步不是继续加功能，而是做三件事：

1. **把工程语言翻译成用户语言**
2. **把安全设置从“开关堆叠”改成“保护级别”**
3. **把零散 CSS 动效收成一套有节奏的动效系统**

---

## 1. 现在做得好的地方

这些不要推翻：

- **视觉识别**：暖灰纸墨底色 + 桃色强调色，和常见的冷色 AI 工具区分明显。
- **主界面结构**：左侧项目/对话、中间阅读区、右侧工作面板，三层关系清楚。
- **阅读宽度**：聊天区约 900px，长文和代码不会拉得过宽。
- **信息密度**：会话行、工具行、状态行都足够紧凑，适合每天使用。
- **功能完整度**：项目、会话分支、搜索、附件、工作面板、浏览器、Computer Use、沙箱、审计日志都在同一个壳里。
- **设置搜索**：设置页有搜索框，这是大产品才有的细节。
- **键盘操作**：⌘N、⌘B、⌘,、⌘⇧L 等快捷键已经覆盖高频动作。
- **安全透明度**：权限、工具审批、沙箱状态、审计日志都能看见，没有假装“绝对安全”。
- **减少动态效果**：已经有全局 `prefers-reduced-motion` 处理，这是很好的基础。

## 2. 体验分层：用户实际会经历的三段

### 第一段：第一次打开

用户心里的问题不是“Pi runtime 是什么”，而是：

1. 这是干什么的？
2. 我现在要做什么？
3. 会不会很复杂？
4. 会不会动我的文件？

当前首屏出现：
- “先安装 Pi 运行时”
- “Pi Desktop 需要 pi 来处理模型、工具和会话”
- “配置模型”
- “打开项目”
- “内置 Pi 1.5.0”
- 安装日志

这对工程师很清楚，对普通用户是**同时抛出四个概念**。

### 第二段：第一次完成任务

用户需要理解：
- 项目 = 我在哪个文件夹里工作
- 对话 = 一次任务
- 模型 = 谁在回答
- 工具调用 = Pi 做了什么
- 审批 = 什么时候问我
- 沙箱 = 它不能碰什么

当前这些概念分散在输入框、设置、权限弹窗和工具行里，缺少一条“从开始到完成”的解释路径。

### 第三段：每天使用

用户开始在意：
- 切换对话是否够快
- 流式输出是否稳定
- 工具行是否太吵
- 设置是否能搜到
- 长对话是否卡
- 错误是否能恢复
- 会不会误点“完全访问”

这一段更多是**流利度和信息节奏**问题，不是功能缺失。

## 3. 动效现状盘点

当前样式里有大量零散动效：

- 约 56 处 `transition`
- 约 25 处 `animation`
- 约 15 个 `@keyframes`
- 时长集中在 0.12s–0.30s，另有 1.1s 循环、1.4s 循环、3.6s 演示动画

### 3.1 现有动效清单

| 区域 | 当前实现 | 感受 | 问题 |
|---|---|---|---|
| 侧栏收起 | 宽度 260ms + 内容透明度 180ms | 有“抽屉”感 | 宽度动画每帧触发布局，聊天区会跟着重排；文字淡出和宽度变化同时发生，容易晕 |
| 消息进入 | 所有 `.message` 200ms 上移 4px | 新消息有生命感 | 打开历史会话时**所有消息一起动**，像页面在闪；长会话更明显 |
| 思考内容展开 | 160ms 淡入 + 上移 | 轻 | 只淡入，没有高度过渡；展开瞬间会跳 |
| 工具卡展开 | 基本无过渡 | 直接 | 展开/收起是瞬切，和消息、思考的节奏不一致 |
| 弹层 / 菜单 | 约 160ms `pop-in` | 轻快 | 起点、缩放、阴影不统一，有的从顶部出现，有的从中心出现 |
| 设置页 | 240ms 上移 8px | 像打开一个面板 | 全屏设置从下方浮起略重；切换分类时没有过渡 |
| 侧栏/按钮 hover | 120–140ms | 灵敏 | 基本没问题，但 hover-only 控件太多 |
| 加载 spinner | 1.1s 三点脉冲 | 可识别 | 多处重复；没有延迟出现，快速操作会闪一下 |
| 顶部进度条 | 1.1s 无限滑动 | 明确 | 和 spinner 同时出现时会有两套“正在运行”的反馈 |
| Chrome 引导 | 3.6s 循环移动文件夹 | 有教学感 | 装饰性循环动画在设置页里偏抢眼 |
| 设置页背景 | `backdrop-filter: blur(12px)` | 高级 | Electron 上长时间开着可能增加 GPU 负担 |

### 3.2 动效的核心问题

不是“动画太多”，而是：

1. **没有动效 token**  
   120、140、150、160、180、200、240、260、300ms 都在用；`ease`、`ease-out`、自定义贝塞尔混用。

2. **没有“只动新内容”的约束**  
   消息进入动画绑在 `.message` 上，历史消息重新挂载也会动。

3. **该动的地方没动**  
   工具卡、思考区、设置分类切换、附件行、队列行，缺少连续的高度/透明度过渡。

4. **不该动的地方太抢**  
   侧栏宽度、全屏设置入场、Chrome 演示、循环脉冲同时存在。

5. **反馈层次不清**  
   一次运行可能同时出现：顶部进度条、spinner、状态点、按钮文字变化。用户不知道看哪个。

### 3.3 建议的动效系统

统一成三档：

```css
--motion-1: 120ms;  /* hover、按下、图标旋转 */
--motion-2: 180ms;  /* 弹层、工具展开、消息进入 */
--motion-3: 240ms;  /* 页面、侧栏、面板 */
--ease-out: cubic-bezier(0.2, 0.8, 0.2, 1);
--ease-in-out: cubic-bezier(0.4, 0, 0.2, 1);
```

规则：

- **只对 `opacity` 和 `transform` 做动画**，避免宽高、top/left 连续变化。
- 侧栏收起用 **180ms**，内容透明度用 **100ms**；不要让聊天区文字跟着淡出。
- 消息进入只给**新追加的消息**加 class，历史会话打开时不动画。
- 工具卡展开用 `grid-template-rows: 0fr → 1fr` 或高度过渡，**160–180ms**，内容淡入 120ms。
- 弹层统一从触发点方向出现，**120ms**，位移不超过 4px，缩放 0.98 → 1。
- 设置页入场改成 **160ms 淡入 + 4px 上移**，或者直接无动画；分类切换不做整页动画。
- 加载状态：**150ms 后才显示 spinner**，避免快速操作闪烁。
- 所有循环动画在窗口隐藏时暂停；`prefers-reduced-motion` 下全部关闭。
- 一次交互最多同时动两个属性，不要同时动宽度、透明度和阴影。

## 4. 流利度：真正影响“快”的地方

### 4.1 会话切换

现在打开会话会重新渲染消息列表，所有消息带 `message-in` 动画，容易造成：

- 整页消息一起上移
- 滚动位置抖动
- 长会话首屏闪一下
- 切换回运行中的会话时，状态和内容不同步

建议：

- 切换会话时**保留现有内容**，顶部只显示 2px 进度线。
- 只在首次为空或超过 300ms 未完成时显示骨架。
- 历史消息**不做入场动画**。
- 恢复滚动位置时不要触发“回到底部”。
- 运行中的会话在后台继续，切换回来直接接上，不要闪 loading。

### 4.2 流式输出

- 文本更新应按帧合并（`requestAnimationFrame`），不要每个 token 触发整棵消息树重渲染。
- 工具卡在流式过程中保持稳定高度，不要因为输出增长而频繁跳动。
- 自动跟随只在用户位于底部时生效；用户上滚后显示“回到最新”，不要抢滚动。
- 代码块、diff、图片加载时保留占位高度，避免布局抖动。

### 4.3 工具调用

当前工具行是紧凑的，这是优点。问题是：

- 展开/收起无过渡，像突然换了一屏。
- 运行中、完成、失败三种状态的视觉差异不够连续。
- 摘要行有时是原始命令，有时是动词短语，阅读节奏不统一。

建议统一摘要格式：

```text
运行了 3 条命令 · 1.2s
读取了 5 个文件 · 0.8s
修改了 2 个文件 · 340ms
```

展开后才显示完整命令、参数、输出。这样用户先看到“做了什么”，而不是“执行了什么协议”。

### 4.4 设置页

- 设置页是全屏的，打开时会遮住对话；这没问题，但要有明确的“返回对话”和“当前分类”提示。
- 11 个分类对老用户够用，对新用户太多。
- 搜索很好，但搜索结果应该显示“所属分类”，并提供“只看常用/显示高级”的过滤。
- 保存类操作要有即时反馈；当前部分设置是失焦保存，用户不确定是否生效。建议统一：保存按钮 + “已保存”短暂反馈，或明确的“自动保存”提示。

### 4.5 加载、空状态、错误

- “正在读取…”出现得太频繁，且没有骨架，页面会先空一下再出现内容。
- 空状态需要三件套：一句解释、一个主按钮、一个例子。
- 错误需要三件套：发生了什么、你可以做什么、如何保留当前工作。
- `stderr`、`JSONL`、`models.json` 这类内容应折叠到“技术详情”，不要放在第一层。

## 5. 交互设计问题清单

### P0：直接影响第一次使用

1. **首次启动概念太多**  
   `Pi 运行时`、`内置 Pi`、`模型服务商`、`API Key`、`项目` 同时出现。  
   建议改成三步：准备 Pi → 选择 AI 模型 → 打开项目。

2. **主按钮不够唯一**  
   缺 Pi 时，安装/重新检测/设置路径/打开项目都在同一屏。  
   建议只保留一个主按钮，其余降级为文字链接。

3. **“配置模型”不是用户目标**  
   用户想的是“让 Pi 能回答”，不是“配置模型”。  
   建议标题改成“选择 AI 模型”，并给出“我有访问密钥 / 使用账号登录 / 使用本地模型”三条路径。

4. **安全设置是开关堆叠**  
   `启用沙箱`、`文件写入范围`、`网络访问`、`额外域名`、`工具审批方式`、`完全访问` 相互影响。  
   建议提供三个预设：  
   - **推荐保护**：只能改当前项目，只访问 AI 服务，高风险操作先问  
   - **只读查看**：只能读，不改文件  
   - **不受限制（仅本次）**：关闭沙箱和审批，红色警告  
   高级用户再展开“自定义”。

5. **“完全访问”风险表达不够直观**  
   现在的描述是“关闭 Pi 沙箱并跳过工具审批”。  
   建议：“Pi 可以修改电脑上的文件并联网，不再逐次询问。只在你完全信任当前任务时使用。”

### P1：影响每天使用

6. **会话权限 chip 太技术**  
   `会话权限`、`沙箱未开启`、`项目只读` 出现在输入框旁边，认知负担高。  
   建议改成 `保护级别：标准 / 只读 / 不受限`，详细解释放到弹层。

7. **hover-only 操作不可发现**  
   消息时间、复制、工具箭头、项目删除都在 hover 才出现。  
   建议：工具箭头默认低透明度常显；操作在 focus-within 时也出现；触屏/无 hover 设备常显。

8. **顶部栏路径和 token pill 对新手无意义**  
   完整路径用等宽字体显示，token 用量常驻。  
   建议：顶栏显示项目名，路径进 tooltip；token 收进“对话详情”，默认不展示。

9. **模型 chip 的 fallback 是英文 `Model`**  
   中文界面出现英文，破坏一致性。  
   建议统一为“模型”，未选择时显示“选择模型”。

10. **混合语言**  
    `Recent projects`、`Computer Use`、`Steering`、`Follow-up`、`Reasoning effort` 等英文和中文混排。  
    建议：主界面中文；功能专名保留英文时，第一次出现加中文解释；高级设置再显示英文原词。

11. **设置分类是按实现划分的**  
    `工具与技能`、`Computer Use`、`网页浏览`、`网络与沙箱` 是按模块划分，不是按用户目标划分。  
    建议按“常用 / AI / 安全与网络 / 数据 / 关于”重组。

12. **重复的风险说明**  
    沙箱说明、工具审批说明、完全访问说明在多个地方重复，而且一处比一处长。  
    建议：每个概念只保留一个“主解释”，其他地方用一句话 + “了解详情”。

13. **提示条和弹窗文案偏长**  
    很多段落 3–5 行，用户会跳过。  
    建议：第一层最多两句话；技术细节放到 `<details>` 或“高级”区域。

### P2：长期打磨

14. **空状态缺少“下一步”**  
    项目为空、会话为空、工作区为空时，应该有一个明确动作，而不是只有说明。

15. **设置保存反馈不统一**  
    有的立即保存，有的失焦保存，有的需要重启。  
    建议统一成“自动保存 + 顶部轻提示”，涉及重启的明确写“新对话生效”。

16. **工作面板术语偏工程**  
    `Artifacts`、`Changes`、`Workspace`、`Session` 对普通用户不直观。  
    建议：`产物`、`改动`、`当前项目`、`本次对话`。

17. **Computer Use / 浏览器模式选择太多**  
    应用内浏览器、独立 Chrome、日常 Chrome、CDP、扩展桥，用户很难选。  
    建议：默认推荐“应用内浏览器”；其他模式放到“高级连接方式”，每个模式用一句“适合谁”。

18. **键盘可达性还可以更好**  
    全局 focus ring 已有，但部分自定义按钮、工具行、项目行需要确认 Tab 顺序和 focus 可见性。  
    建议做一次纯键盘走查：Tab、Shift+Tab、Enter、Space、Esc、方向键。

## 6. UI 视觉细节

### 6.1 字体层级太平

当前大量文字集中在 10.5–13.5px：

- 正文 13.5
- 说明 11.5–12.5
- 元信息 10.5
- 设置标题 12

结果是“所有东西都重要”，阅读时缺少停顿。建议：

```text
页面标题      20–22
区块标题      15–16
正文          14
说明          12.5
元信息        11
```

不要靠 0.5px 的差异建立层级。

### 6.2 浅色主题对比度不足

按当前颜色计算：

- 深色 `--text-faint #a29d94` on `#1c1d20`：约 **6.25:1**，合格
- 浅色 `--text-faint #837c72` on `#f8f6f2`：约 **3.82:1**，低于小字号 4.5:1
- 浅色强调色 `#b25f31` on `#f8f6f2`：约 **4.25:1**，小字号也偏低

建议：

- 浅色 `--text-faint` 改到 `#746d63` 左右（约 4.7:1）
- 浅色强调色改到 `#a04f25` 左右（约 5.3:1）
- 10.5px 的元信息不要使用最低对比色

### 6.3 边框和卡片太多

设置页、权限页、工具卡、项目行都用了边框 + 背景 + 圆角。  
建议减少“卡片套卡片”：

- 一级分组用留白和区块标题
- 二级行用 hover 背景，不必每行都有边框
- 只有需要强调的块（风险、空状态、主操作）使用边框/底色

### 6.4 颜色语义要更严格

- 桃色：主操作、当前选中、品牌
- 绿色：成功、已连接、已保护
- 黄色：需要注意、受限
- 红色：危险、失败、不可逆

不要让桃色同时承担“链接 hover”“选中”“警告”等多种语义。

### 6.5 顶部栏

- 路径用等宽字体，视觉上像调试信息。
- 建议显示项目名 + 会话名；路径放到 tooltip 或“详情”。
- token pill 默认隐藏，或改成“用量”并只在悬停显示明细。

## 7. 文案：从“实现说明”改成“用户结果”

### 7.1 文案原则

1. **先说结果，再说机制**  
   “Pi 只能改当前项目” 比 “workspace-write 白名单” 更有用。

2. **一句话只做一个判断**  
   不要把“是什么、为什么、风险、例外”塞进一句。

3. **技术名词只出现在高级区域**  
   沙箱、域名、代理、JSONL、stderr、provider、base URL、MCP 都可以保留，但不要出现在第一次配置的主路径。

4. **错误必须可行动**  
   每一条错误至少包含：发生了什么 + 你可以做什么 + 当前内容是否保留。

5. **统一称呼**  
   对话、项目、模型服务、访问密钥、保护级别、操作记录、思考深度。

### 7.2 术语替换表

| 现在 | 建议主界面 | 高级区域保留 |
|---|---|---|
| Pi 运行时 | Pi 引擎 / 核心组件 | runtime |
| 安装 Pi | 准备 Pi | install runtime |
| 服务商 | AI 服务 / 模型来源 | provider |
| API Key | API Key（保留） | API Key |
| models.json | 模型设置 | models.json |
| 沙箱 | 受保护模式 | sandbox |
| workspace-write | 可以修改当前项目 | workspace-write |
| read-only | 只能阅读 | read-only |
| 域名 | 网站地址 | domain |

## 8. 设置页：不重排，做轻量优化

已经确认：**不采用 5 组重排**，保留现有 11 个分类。现有分类对老用户已经形成记忆，重排的收益小于迁移成本。

保留：

```text
常规 / 模型 / 工具与技能 / 外观 / 会话 /
Computer Use / 网页浏览 / 网络与沙箱 /
使用情况与费用 / 键盘快捷键 / 关于
```

只做三件事：

1. **每个分类顶部加一句状态摘要**  
   例如网络与沙箱：

   ```text
   当前：沙箱开启 · 只能修改当前项目 · 只允许 AI 服务和指定网站
   ```

2. **把重复的长解释收进“高级”折叠**  
   第一层只留一句结果，不在每个设置项里重复“沙箱是什么”。

3. **保留技术名词，但把说明写成结果**  
   `API Key`、`沙箱`、`服务商`、`自动压缩上下文` 这些用户已经会遇到的词不强行改名；改的是它们下面那句解释。

这样既不让老用户重新学习设置，也能降低第一次使用的理解成本。

## 9. 首次启动重构

推荐只保留三步：

```text
1  准备 Pi        [自动完成]
2  选择 AI 模型   [主操作]
3  打开项目       [次操作 / 先聊聊]
```

具体：

- **第 1 步**：如果内置 Pi 已就绪，直接显示“已准备好”，不要出现 runtime、seed、版本号。  
  如果缺失，只保留“一键准备”主按钮 + “我已安装，去检测”文字链接。
- **第 2 步**：三个卡片：
  - 我有访问密钥
  - 使用账号登录
  - 使用本地模型（高级）
- **第 3 步**：最近项目 + 打开文件夹 + “先随便聊聊”。
- 只允许一个主按钮；步骤完成后自动进入下一步。
- 技术细节（Pi 路径、版本、安装日志、seed）统一放到“高级”或“关于”。
- 首次真正执行工具时再解释权限，不要在首屏一次性讲完。

## 10. 交互与动效的验收标准

### 动效

- 打开历史会话时，历史消息**不播放进入动画**。
- 侧栏收起/展开不超过 180ms，聊天区无明显文字重排闪烁。
- 工具卡展开/收起有连续高度过渡，箭头旋转 120ms。
- 弹层从触发点方向出现，位移 ≤4px。
- 所有循环动画在 `prefers-reduced-motion` 下停止。
- 快速操作（<150ms）不出现 spinner 闪烁。

### 流利度

- 切换会话首屏不空白；慢于 300ms 才显示骨架。
- 流式输出时滚动稳定，用户上滚后不被拉回底部。
- 长会话打开不出现整页消息动画。
- 设置搜索输入无卡顿，结果切换无明显布局跳动。

### 文案

- 首次启动主路径不出现：runtime、sandbox、provider、base URL、models.json、JSONL、stderr、token。
- 每个设置项标题不超过 12 个汉字，说明不超过两行。
- 每个错误都有“下一步”动作。
- 同一概念只有一个主称呼。

### 可访问性

- 浅色主题小字号对比度 ≥4.5:1。
- 所有交互元素有 `:focus-visible`。
- hover-only 操作在 focus/无 hover 设备上可见。
- 关键状态不只靠颜色区分。
- 流式输出有 `aria-live` 或等价的状态提示。

## 11. 优先级路线图

### P0：先让新用户能走通

1. 首次启动三步化，去掉首屏技术名词。
2. “配置模型”改成“选择 AI 模型”，提供三条路径。
3. 安全设置改成“保护级别”预设 + 高级自定义。
4. 全局术语替换第一轮（运行时/服务商/沙箱/审批/上下文）。
5. 修复消息入场动画：只动新消息。
6. 浅色主题对比度修正。

### P1：让每天使用更顺

7. 动效 token 化，统一 120/180/240ms。
8. 工具卡、思考区、附件行加连续过渡。
9. 会话切换延迟 spinner + 骨架，不闪空白。

### P2：长期打磨

14. 键盘全流程走查。

16. 工作面板术语统一。

## 12. 不建议做的事

- 不要为了“高级感”增加更多全屏动画、模糊、发光。
- 不要把技术词全部删掉；工程师仍然需要，只是放到高级区域。
- 不要把所有设置塞进一个“高级”黑洞；常用项仍要可搜索、可发现。
- 不要用颜色作为唯一状态信号。
- 不要继续给每个组件单独写一套 duration/easing。
- 不要在没有真实长会话、慢网络、浅色主题测试的情况下宣布“流利度完成”。
